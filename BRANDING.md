# The Celandine branding

The display name is **The Celandine**; the official wordmark reads **THE CELANDINE**. The supplied reference guides the horizontal emblem, classical serif lettering, larger initial capitals, and spacing. The original font was not present or identified. Cinzel Regular is a close Roman serif approximation, not an exact font match. The unmodified font and SIL Open Font License are bundled in `assets/fonts/cinzel/`, from [the font author's repository](https://github.com/NDISCOVER/Cinzel). Normal interface text keeps the existing sans-serif fonts.

`includes/branding.php` provides the full, compact, and icon-only lockups, one wordmark treatment, document styling, and an email header. Existing `buildingicon.php` calls render the shared full lockup; containing layouts scale it through `assets/css/branding.css`. The shared head loads and preloads the local font and exposes the same component through a template for Digital Condo ID and loading UI. New screens should call `brandHtml()` or `brandHtml('compact')` instead of copying brand markup.

Dark Mode uses the original white `celandine.svg`; Light Mode uses the original orange `celandineorange.svg` with a readable darker orange wordmark. Both SVG files are unchanged. The existing theme controller handles switching and preference persistence. White-paper receipts, reports, and print views use the orange emblem. Receipt and QR report PDFs embed the same local font without remote dependencies. Transaction fields, amounts, references, and calculations are unchanged.

Email headers use a transparent PNG rendered from the same component and font, attached through the existing PHPMailer transport as `cid:celandine-brand`. This avoids requiring email clients to support SVG or downloadable fonts. Regenerate the two email header assets after a deliberate branding style change with `node scripts/test_loading_ui_browser.cjs --branding-only`. Images blocked by the mail client show the text alternative. Existing recipients, verification/reset links and tokens, queue keys, SMTP settings, and notification logic remain unchanged. Known obsolete display names in `CONDO_MAIL_FROM_NAME` are mapped to the new display name; unrelated custom/legal sender names remain intact.

Do not rename technical identifiers, storage keys, URLs, email addresses, the database, or existing records. The legacy `SEMAPHORE_SENDER_NAME` is intentionally retained because it identifies a provider-approved SMS sender; outbound message text uses The Celandine. Change that provider setting only after the replacement sender has been approved. Historical messages, saved receipts, and previously queued notification payloads are not rewritten.

Validation uses `scripts/test_ui_redesign.php --preview` with a disposable database. Run `node scripts/test_theme_browser.cjs <fixture-base-url> --branding-only` for role dashboards, public account screens, passes, both themes, and desktop/mobile alignment. The existing loading, Digital ID, visitor, billing, and role tests verify the retained workflows. A sample paid fixture receipt and synthetic QR report are rendered through the actual Dompdf templates and inspected as PNGs. Actual mail delivery and client image-blocking behavior still need a controlled manual check; this task does not send mail or exercise live PayMongo transactions.

The branding verification run passed 1,522 route/asset/CSRF checks across 89 role/page combinations, 370 branding layout/theme checks, 27 loading interaction checks, and 292 Digital ID browser regression checks (`--quick`, including actual QR screenshot decoding). PHP syntax checks passed for 191 application files. Sample receipt and QR report PDFs were visually inspected; receipt reference, payer and amount were also checked in extracted text. Email MIME preparation verified the embedded header and retained links without sending. The existing provider-approved SMS sender is the only intentionally retained obsolete brand display name in application configuration; existing contact email addresses also remain unchanged.

- Documents and communications: `resident/payment_receipt.php`, `includes/qr_scan_report.php`, `superadmin/analytics.php` print export, `resident_service_pass.php`, `parking_pass.php`, `includes/property_gate_pass_page.php`, `digital_id_verify.php`, `includes/notify.php`, password-reset/verification email templates, and SMS message text.
